# E6 결과·카탈로그 화면 작업 상세

E6는 E4의 분석 상태와 E5의 정규화된 Finding을 사용자에게 보여주는 화면을 구현한다. E4와 E5가 실제 데이터를 만들기 전에는 화면 구조·표시 필드·상태·API 계약만 확정하며, 실제 화면 구현과 fixture 기반 검증은 두 에픽 구현 뒤 진행한다.

## E6-01, E6-02 분석 이력과 상태 화면 흐름

- 상태: 결정 완료, 구현 전
- 요구사항 매핑: SFR-015, SFR-016, SEC-003, SEC-009, TST-007
- 결정과 근거: 분석 상세는 `/projects/:projectId/analyses/:analysisId` 단일 경로를 사용한다. 프로젝트 상세에서 분석 이력을 선택하면 `PENDING`·`RUNNING`은 상태 화면, `FAILED`는 실패 상태, `COMPLETED`는 같은 경로의 결과 목록을 표시한다. 완료 뒤 별도 결과 경로로 이동시키지 않는다. E4의 ADR-028 폴링 규칙을 그대로 사용한다.
- 완료 조건:
  - 권한 있는 USER와 ADMIN이 프로젝트 상세에서 분석 이력을 조회하고 분석 상세로 이동할 수 있다.
  - `PENDING`·`RUNNING`은 3초 폴링, `COMPLETED`는 같은 경로의 결과 목록, `FAILED`는 역할별 실패 안내를 표시한다.
  - 분석 조회 응답의 실제 `project_id`를 브레드크럼과 뒤로가기 기준으로 사용한다. URL의 `:projectId`와 다르면 실제 소속 프로젝트의 정규 경로로 `replace` 이동한다.
  - USER는 일반 실패 안내만, ADMIN은 허용된 오류 코드·상세 메시지·실행 로그와 재실행 행동을 본다.
  - 네트워크 또는 5xx 상태 조회 실패는 분석 실패로 바꾸지 않고 수동 새로고침을 제공한다.
- 결정 필요: 없음
- 테스트: E6-09에서 상태별 화면 전환, 폴링 시작·중단, 실제 소속 프로젝트 경로 정규화, USER의 관리자 상세 미노출을 검증한다.

## E6-03 진단 결과 목록, 필터와 페이지네이션

- 상태: 결정 완료, 구현 전
- 요구사항 매핑: SFR-016, SFR-017, DAR-006, DAR-008, SEC-003, TST-007
- 결정과 근거: 결과 목록은 정보 밀도를 유지하기 위해 심각도, KISA 매핑 상태, 언어만 필터로 제공한다. 기본 정렬은 `CRITICAL`, `HIGH`, `MEDIUM`, `LOW`, `UNKNOWN` 심각도 순, 상대 파일 경로 오름차순, 시작 줄 오름차순, Finding ID 오름차순이다. 마지막 ID 정렬은 offset 페이지네이션에서도 결과가 중복되거나 빠지지 않게 한다. `GET /api/findings`는 목록 전용의 경량 응답 스키마를 사용하고, 메시지·탐지 근거·코드 조각·조치 권고·엔진 규칙 식별자·기준 식별자·원본 결과는 `GET /api/findings/{finding_id}` 상세 응답에서만 제공한다. 자세한 근거는 ADR-037을 따른다.
- 완료 조건:
  - 목록은 심각도, 진단 항목명과 KISA 코드, 상대 파일·시작/끝 줄, 언어, 신뢰도, KISA 매핑 상태를 표시한다.
  - 필터는 심각도, `KISA_MAPPED`/`UNMAPPED`, `JAVA`/`JAVASCRIPT`/`PYTHON`만 제공한다. 텍스트·기준 코드·신뢰도 검색은 MVP에서 제외한다.
  - `GET /api/findings`는 서버에서 `severity`, `mapping_status`, `language`, `limit`, `offset`을 처리하고 `items`, `total`, `limit`, `offset`을 반환한다.
  - 목록 `items`는 `severity`, `rule_name`, `kisa_code`, `file_path`, `line`, `end_line`, `language`, `confidence`, `mapping_status`만 포함하는 별도 경량 스키마를 사용한다. 상세 응답만 `engine_rule_id`, `criterion_id`, 메시지, 탐지 근거, 코드 조각, 조치 권고와 ADMIN 전용 `raw_result`를 포함한다.
  - 기본 `limit`은 50이고 서버 최대값은 100이다.
  - 목록은 심각도, 파일 경로, 시작 줄, Finding ID의 완전한 순서로 안정적으로 표시된다.
- 결정 필요: 없음
- 테스트: E6-09에서 세 필터의 단독·조합 결과, 빈 필터 결과, 페이지 이동, 동일 심각도·파일·줄 Finding의 안정 순서, 서버 최대 limit을 검증한다.

## E6-04, E6-05 진단 결과 상세와 관리자 실행 정보

- 상태: 결정 완료, 구현 전
- 요구사항 매핑: SFR-016, SFR-017, DAR-006, DAR-008, SEC-003, TST-007
- 결정과 근거: 완료 분석의 결과는 왼쪽 목록과 오른쪽 조회 패널을 함께 보이는 분할 화면으로 표시한다. 상세 패널이 열려도 목록의 필터·페이지·스크롤 위치는 유지하며, 목록과 상세 패널은 각각 독립적으로 스크롤한다. 패널을 닫으면 목록은 전체 작업 폭을 다시 사용한다. 이는 입력 행동에 쓰는 400px `ActionDrawer`와 다르며, 화면 이동이나 오버레이 없이 여러 결과를 빠르게 대조하기 위한 조회 전용 패널이다. 자세한 근거는 ADR-038을 따른다.
- 완료 조건:
  - 상세 패널은 심각도와 진단 항목명을 먼저, KISA 매핑 상태·상대 파일 경로·시작/끝 줄·언어·신뢰도를 다음으로 표시한다.
  - 메시지, 탐지 근거, 분석 시점 코드 조각과 조치 권고를 표시한다. 코드 조각을 읽지 못한 결과도 나머지 상세 정보는 표시한다.
  - ADMIN은 Finding 원본 결과를 추가로 조회하고, USER에게는 해당 필드와 영역을 렌더링하지 않는다.
  - `FAILED` 분석에서 USER는 일반 실패 안내만, ADMIN은 오류 코드·상세 메시지·제한된 실행 로그와 현재 소스 재분석 행동을 본다. 실행 로그는 개별 Finding이 아닌 분석 상태 화면에서만 표시한다.
  - 목록과 상세 패널의 스크롤은 서로 독립적이며, 상세 패널을 닫아도 목록 상태가 초기화되지 않는다.
- 결정 필요: 없음
- 테스트: E6-09에서 USER의 원본 결과 미노출, ADMIN의 원본 결과 노출, 실패 상태별 역할 차이, 목록 상태 유지와 독립 스크롤을 검증한다.

## E6-06, E6-07 KISA 카탈로그 조회·검색·필터

- 상태: 결정 완료, 구현 전
- 요구사항 매핑: SFR-012, SFR-013, DAR-007, SEC-003, TST-006
- 결정과 근거: 49개 고정 규모의 카탈로그는 서버 검색 API를 새로 만들지 않고, 목록을 받은 뒤 클라이언트에서 `kisa_code`, 명칭, 분류로 검색하고 `지원`·`부분 지원`·`미지원` 구현 상태로 필터링한다. 선택 항목은 왼쪽 목록과 오른쪽 조회·수정 패널 구조로 보여 준다. USER는 같은 내용을 읽기 전용으로 보고, ADMIN만 패널을 수정 상태로 전환할 수 있다.
- 완료 조건:
  - 목록은 KISA 코드, 분류, 항목 번호, 명칭, 구현 상태를 표시하고 KISA 코드·명칭·분류 검색과 구현 상태 필터를 제공한다.
  - USER에게 수정·등록·비활성화 행동을 렌더링하지 않는다.
  - ADMIN은 선택한 항목의 설명, 참조 정보, 활성 여부, 기본 심각도, 구현 상태, 조치 권고만 수정할 수 있다. KISA 코드, 명칭, 분류, 기준 식별자, 항목 번호는 수정하지 않는다.
  - 삭제 API나 삭제 UI는 제공하지 않으며, 더 이상 쓰지 않는 항목은 `active=false`로 비활성화한다.
- 결정 필요: 없음
- 테스트: E6-09에서 검색·필터 조합, 빈 필터 결과, USER 읽기 전용, ADMIN 수정 가능 범위와 비활성화를 검증한다.

## E6-08 공통 상태와 오류 처리

- 상태: 결정 완료, 구현 전
- 요구사항 매핑: SFR-015, SFR-016, SEC-003, SEC-009, TST-007, TST-008
- 결정과 근거: 짧은 초기 로딩은 화면별 스켈레톤 또는 로딩 표시로 처리한다. 분석 이력 없음, Finding 없음, 필터 결과 없음은 각각 다른 빈 상태로 표시하고 마지막 경우에는 필터 초기화 행동을 제공한다. 기존 E2 인증 흐름을 재사용해 401만 로그인 이동으로 처리한다. 네트워크·5xx 오류는 세션 만료나 분석 실패로 바꾸지 않고 현재 데이터를 유지한 채 해당 화면의 일반 안내와 재시도를 제공한다.
- 완료 조건:
  - 401은 기존 로그인 만료 안내와 로그인 이동을 사용하고, 403은 `이 기능은 관리자만 사용할 수 있습니다.`, 404는 `요청한 정보를 찾을 수 없습니다.`를 표시한다.
  - 네트워크·5xx 오류는 내부 상세를 노출하지 않고 화면별 재시도 행동을 제공하며, 기존 성공 데이터를 임의로 지우지 않는다.
  - 분석 이력 없음, Finding 없음, 필터 결과 없음이 서로 구분되어 표시된다.
- 결정 필요: 없음
- 테스트: E6-09에서 401·403·404·5xx, 세 빈 상태, 재시도와 기존 데이터 유지 동작을 검증한다.

## E6-09 화면 흐름·Pen 대조 테스트

- 상태: 결정 완료, 구현 전
- 요구사항 매핑: TST-006, TST-007, TST-008
- 결정과 근거: 완료 판정은 기능 흐름 테스트와 E0 Pen 초안의 구조 대조를 함께 사용한다. 기능 테스트는 역할별 행동, 인증·권한·오류 상태, 빈 상태, 필터·페이지네이션, 패널과 등록·수정 API 연결을 검증한다. Pen 대조는 다크 톤, 왼쪽 목록·오른쪽 상세 패널, 독립 스크롤, 400px `ActionDrawer`, 정보 표시 순서 같은 구조 수준으로 한정한다. 픽셀 단위 시각 회귀는 MVP 완료 조건에 포함하지 않는다. Pen 초안과 API 계약이 충돌하면 API 계약과 ADR을 우선한다.
- 완료 조건:
  - 프론트 테스트가 ADMIN·USER의 결과·카탈로그 흐름과 권한별 비노출을 검증한다.
  - 분석 상태 폴링의 시작·중단·완료·실패 전환과 목록 필터·페이지네이션을 검증한다.
  - 로딩·빈 상태·401·403·404·네트워크 또는 5xx 오류를 검증한다.
  - 구현 화면이 Pen의 구조·정보 순서·공통 패널 규칙을 따르는지 수동으로 확인한다. 화면 캡처 첨부는 필수 완료 조건으로 두지 않는다.
- 결정 필요: 없음

## E6-11 관리자 카탈로그 등록·수정

- 상태: 결정 완료, 구현 전
- 요구사항 매핑: SFR-013, DAR-007, SEC-003, TST-006
- 결정과 근거: 신규 등록은 기존 `ActionDrawer`로 제공하고, 기존 항목 수정은 카탈로그 오른쪽 패널에서 제공한다. 등록과 수정의 허용 필드는 기존 API 계약과 ADR-003을 그대로 따른다. E0 Pen 초안의 등록 폼에 있던 조치 권고는 등록·수정 필드를 함께 그린 오래된 시각 초안으로 보고 API를 바꾸지 않는다.
- 완료 조건:
  - ADMIN 등록 Drawer는 `kisa_code`, 명칭, 분류, 기본 심각도를 필수로 받고, 설명·기준 식별자·항목 번호·참조 정보를 선택으로 받는다. 활성 여부 기본값은 `true`, 구현 상태 기본값은 `미지원`이다.
  - 등록 Drawer는 조치 권고를 보내지 않는다. 조치 권고는 기존 항목의 오른쪽 수정 패널에서만 수정한다.
  - 중복 KISA 코드 `409`은 안전한 중복 안내로 표시하고, 성공 뒤 목록과 선택 상태를 갱신한다.
  - USER에게 등록 Drawer와 수정 상태 전환을 렌더링하지 않는다.
- 결정 필요: 없음
- 테스트: E6-09에서 필수·선택 필드, 중복 등록, 등록 뒤 갱신, USER 비노출과 수정 필드 범위를 검증한다.

## E6-12 관리자 프로젝트 생성·수정

- 상태: 결정 완료, 구현 전
- 요구사항 매핑: SFR-004, SEC-003, TST-002
- 결정과 근거: 프로젝트 생성과 수정은 공통 `ActionDrawer`를 사용한다. 프로젝트 생성에는 언어 선택을 두지 않으며, 언어는 E3 소스 등록 성공 뒤 시스템이 자동 식별한다. 서버는 같은 이름을 거부하지 않고 고유한 표시명을 만들 수 있으므로, 프론트는 응답의 실제 프로젝트 ID와 이름을 기준으로 목록·상세 이동을 처리한다.
- 완료 조건:
  - ADMIN 생성 Drawer는 이름을 필수, 설명을 선택으로 받고 성공 시 닫힌 뒤 응답의 실제 프로젝트 상세로 이동한다.
  - ADMIN 수정 Drawer는 이름과 설명만 수정한다. 대상 언어와 소스 상태는 수정 입력으로 제공하지 않는다.
  - USER에게 프로젝트 생성·수정 행동을 렌더링하지 않는다.
- 결정 필요: 없음
- 테스트: E6-09에서 ADMIN 생성·수정·서버가 바꾼 표시명 처리와 USER 비노출을 검증한다.

- E6-04, E6-05: 진단 결과 상세 패널과 관리자 전용 원본 결과·실행 로그
- E6-06, E6-07: KISA 49개 카탈로그 목록, 검색, 구현 상태 필터
- E6-08: 로딩·빈 결과·오류·권한 없음 상태
- E6-09: 전체 화면 흐름 테스트
- E6-11, E6-12: 관리자 카탈로그 등록·수정과 프로젝트 생성·수정 ActionDrawer
