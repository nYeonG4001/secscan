# API 계약 초안

이 문서는 MVP 구현 전에 프론트와 백엔드가 공유하는 API 방향을 정리한다. 실제 경로와 필드가 변경되면 관련 ADR과 요구사항 검증표를 함께 갱신한다.

## 공통 규칙

- 프론트엔드가 사용하는 공개 경로는 `/api`다. 개발 프록시가 `/api`를 제거해 백엔드의 실제 경로로 전달한다.
- 백엔드에 직접 요청할 때는 `/auth`, `/projects`처럼 `/api`가 없는 경로를 사용한다.
- 보호된 API는 `HttpOnly` 세션 쿠키를 요구한다. 프론트는 인증 토큰을 브라우저 저장소에 저장하거나 Authorization 헤더로 전달하지 않는다.
- 프로젝트 생성, 수정, 소스 등록, 접근권한 부여와 해제처럼 서버 데이터를 바꾸는 요청은 `X-CSRF-Token` 헤더를 요구한다.
- 관리자 전용 API는 일반 사용자 요청을 거부한다.
- 프로젝트, 분석, 진단 결과는 저장된 관계와 사용자 권한을 함께 검증한다.
- 권한이 없는 프로젝트 자원은 404로 응답한다.
- 관리자 전용 오류와 실행 로그는 일반 사용자 응답에 포함하지 않는다.
- `source_snapshot_location` 같은 서버 내부 저장 위치는 어떤 API 응답에도 포함하지 않는다.

## 인증

### `POST /api/auth/login`

권한: 공개

요청:

```json
{
  "email": "admin@secscan.io",
  "password": "비밀번호"
}
```

`email`은 MVP의 계정 식별자이며 유효한 이메일 형식이어야 한다.

`active=false` 계정은 로그인할 수 없다. 서버는 계정의 활성 여부를 알리는 대신 일반 `401 Unauthorized` 응답을 반환한다.

응답:

```json
{
  "email": "admin@secscan.io",
  "role": "ADMIN"
}
```

서버는 응답 본문의 인증 토큰 대신 `HttpOnly` 세션 쿠키와 CSRF 쿠키를 발급한다. 운영 세션 쿠키는 `Secure`, `HttpOnly`, `SameSite=Strict`, `Path=/` 속성을 사용한다. 세션의 절대 만료 시간은 24시간이며, MVP에서는 유휴 시간 만료와 토큰 갱신을 제공하지 않는다.

MVP에서는 회원가입과 비밀번호 재설정을 제공하지 않는다.

보호된 API는 세션 토큰 서명과 만료 시각뿐 아니라, 토큰의 사용자 계정을 다시 조회해 `active=true`인지 확인한다. 비활성 계정의 기존 세션도 일반 `401 Unauthorized` 응답으로 거부한다.

### `GET /api/auth/me`

권한: 로그인 사용자

응답:

```json
{
  "email": "admin@secscan.io",
  "role": "ADMIN"
}
```

프론트는 앱 시작과 새로고침 때 현재 역할을 확인하는 용도로 사용한다. 비밀번호, 비밀번호 해시, 활성 상태, 인증 토큰은 반환하지 않는다.

### `POST /api/auth/logout`

권한: 공개

세션과 CSRF 쿠키를 만료시킨다. 이미 만료되었거나 없는 세션에도 같은 성공 응답을 반환해 인증 상태를 노출하지 않는다.

## 프로젝트

### `GET /api/projects`

권한: 로그인 사용자

관리자는 전체 프로젝트를, 일반 사용자는 접근권한이 있는 프로젝트만 조회한다.

관리자는 `PROJECT_ACCESS` 행이 없어도 모든 프로젝트를 조회하고 관리한다. 일반 사용자만 프로젝트별 접근권한 행이 필요하다.

일반 사용자는 권한이 부여된 프로젝트를 분석 이력이 없어도 조회할 수 있다. 이 경우 화면은 분석 이력이 없다는 빈 상태를 표시한다.

접근권한 해제는 프로젝트와 분석 데이터를 삭제하지 않는다. 권한이 해제된 일반 사용자의 목록에서는 해당 프로젝트를 숨기고, 직접 주소 접근은 404로 응답한다.

프로젝트 목록과 상세 응답의 `source_status`는 저장 필드가 아닌 계산값이다. `source_location`이 비어 있으면 `NEEDS_UPLOAD`, 존재하면 `REGISTERED`를 반환한다. `source_location` 자체는 서버 내부 정보이므로 응답에 포함하지 않는다.

### `GET /api/projects/{project_id}`

권한: 해당 프로젝트 접근권한이 있는 사용자

관리자는 모든 프로젝트를, 일반 사용자는 현재 접근권한이 있는 프로젝트만 조회한다. 존재하지 않는 프로젝트와 권한 없는 프로젝트는 모두 404로 응답한다.

### `POST /api/projects`

권한: 관리자

프로젝트명과 선택 입력인 설명을 입력받는다. `target_languages`는 프로젝트 생성 API에서 받지 않는다. MVP의 소스 유형은 파일 업로드이며, 소스 등록이 성공하면 시스템이 업로드 파일에서 `JAVA`, `JAVASCRIPT`, `PYTHON` 언어를 자동 식별해 `target_languages`, `source_type`, `source_location`을 기록한다.

같은 프로젝트명을 등록하면 시스템이 뒤 번호를 붙여 고유한 표시명을 저장한다. 예를 들어 `보안 교육 샘플`이 이미 있으면 다음 등록명은 `보안 교육 샘플 (1)`이 된다.

### `PATCH /api/projects/{project_id}`

권한: 관리자

프로젝트명과 설명을 수정한다. `target_languages`는 소스 등록 과정에서 시스템이 갱신하므로 요청으로 수정할 수 없다.

MVP에서는 `DELETE /api/projects/{project_id}`를 제공하지 않는다. 프로젝트 삭제에 따른 분석 이력과 진단 결과 처리 정책은 후속 범위에서 결정한다.

### `PUT /api/projects/{project_id}/source`

권한: 관리자

프로젝트의 현재 소스를 ZIP 파일로 교체한다. 요청은 `multipart/form-data`이고 `file` 필드에 ZIP 하나를 포함한다. 새 소스 등록은 분석을 자동 실행하지 않는다.

서버는 ZIP 원본 크기, 실제 압축 해제 크기, 파일 수, 개별 파일 크기, 압축 비율, 경로와 링크, 지원 소스 파일을 검증한 뒤에만 현재 소스를 교체한다. 성공하면 `source_type`, 내부 `source_location`, 자동 감지한 `target_languages`를 갱신한다. 서버 내부 경로와 업로드 파일명은 응답에 포함하지 않는다.

프로젝트에 `PENDING` 또는 `RUNNING` 분석이 있으면 현재 소스와 진행 중 분석의 대상을 혼동하지 않도록 업로드를 거부한다. 완료 또는 실패한 분석은 새 소스 등록을 막지 않는다.

성공 응답:

```json
{
  "project_id": 12,
  "source_status": "REGISTERED",
  "target_languages": ["JAVA", "PYTHON"]
}
```

업로드 검증 오류는 프론트가 문구를 안전하게 선택할 수 있도록 `code`만 반환한다. 상세 원인과 원본 경로는 서버 로그에만 남긴다.

| HTTP 상태 | `code` | 의미 |
|---:|---|---|
| 409 | `ANALYSIS_ACTIVE` | 진행 중 분석이 있음 |
| 409 | `UPLOAD_IN_PROGRESS` | 같은 프로젝트의 소스 업로드가 진행 중임 |
| 413 | `ARCHIVE_TOO_LARGE` | ZIP 원본 크기 초과 |
| 422 | `ARCHIVE_LIMIT_EXCEEDED` | 압축 해제 제한 초과 |
| 422 | `UNSAFE_ARCHIVE` | 위험한 경로 또는 링크 |
| 422 | `NO_SUPPORTED_SOURCE` | 지원 소스 파일 없음 |

401, 403, 404는 공통 인증, 권한, 자원 정책을 따른다.

### `POST /api/projects/{project_id}/access`

권한: 관리자

요청 본문은 일반 사용자의 이메일을 받는다. 서버는 내부적으로 해당 사용자 ID를 찾아 접근 관계를 저장한다. 존재하지 않는 이메일 또는 프로젝트는 404, ADMIN 계정 대상은 422, 이미 부여된 접근권한은 409로 응답한다.

접근권한 생성과 목록 응답은 관계의 `user_id`와 함께 `user_email`을 포함한다. 화면은 이메일을 표시하고, 권한 해제 요청에는 내부 `user_id`를 사용한다.

### `DELETE /api/projects/{project_id}/access/{user_id}`

권한: 관리자

프로젝트 접근권한을 해제한다. 존재하지 않는 접근 관계는 404로 응답하며, 프로젝트와 분석 이력은 삭제하지 않는다.

## 분석

### `POST /api/analyses`

권한: 관리자

프로젝트의 현재 등록 소스를 기준으로 분석 작업을 생성한다. 분석은 `PENDING`, `RUNNING`, `COMPLETED`, `FAILED` 상태를 사용한다.

분석 행은 생성 시점의 분석 엔진 또는 방식과 실제 적용할 언어 목록을 함께 저장한다. 이 값은 이후 프로젝트의 분석 언어 설정이 바뀌어도 변경하지 않는다.

`FAILED`의 세부 원인은 관리자 응답의 오류 코드와 상세 메시지로 제공한다. 일반 사용자 응답에는 일반적인 실패 안내만 제공한다.

같은 프로젝트에 `PENDING` 또는 `RUNNING` 분석이 있으면 새 분석을 생성하지 않고 409 응답과 현재 분석 정보를 제공한다. 완료 또는 실패한 분석에서 다시 분석을 요청하면 기존 분석 행을 수정하지 않고, 요청 시점의 프로젝트 현재 소스를 대상으로 새 분석 행을 만든다. 과거 분석 스냅샷을 선택한 재실행은 MVP에서 제공하지 않는다. 같은 프로젝트의 소스 업로드가 진행 중이면 업로드 완료 뒤에만 분석을 시작할 수 있다.

활성 분석 중복 응답:

```json
{
  "code": "ANALYSIS_ACTIVE",
  "analysis_id": 42,
  "status": "RUNNING"
}
```

| HTTP 상태 | `code` | 의미 |
|---:|---|---|
| 409 | `ANALYSIS_ACTIVE` | 같은 프로젝트에 `PENDING` 또는 `RUNNING` 분석이 있음 |
| 409 | `SOURCE_UPLOAD_IN_PROGRESS` | 같은 프로젝트의 소스 업로드가 진행 중임 |

### `GET /api/analyses?project_id={project_id}`

권한: 해당 프로젝트 접근권한이 있는 사용자

프로젝트의 분석 이력을 조회한다. 일반 사용자 응답은 상태, 시각, 실행 요약, 일반적인 실패 안내만 포함한다. 관리자 응답은 여기에 분석 엔진 또는 방식, 분석 시점 언어 목록, 상세 오류와 최대 64 KiB의 `execution_log`를 추가한다. 서버 내부 스냅샷 위치와 원본 결과 경로는 두 응답 모두에 포함하지 않는다.

일반 사용자는 상태와 결과 요약을 조회할 수 있다. `FAILED` 상태의 상세 오류와 실행 로그는 일반 사용자 응답에 포함하지 않고, 일반적인 실패 안내만 제공한다. 실행 로그에는 Semgrep의 표준 오류와 실행 단계 정보만 제한적으로 기록하며, 서버 내부 경로, 실행 명령, 환경변수, 업로드 원본 파일명은 저장과 응답 모두에서 제외한다.

### `GET /api/analyses/{analysis_id}`

권한: 분석이 속한 프로젝트에 접근권한이 있는 사용자

분석 상태와 결과 요약을 조회한다. ADMIN 응답에만 `error_code`, `error_message`, `execution_log`가 포함된다.

## 진단 결과

### `GET /api/findings?analysis_id={analysis_id}`

권한: 분석이 속한 프로젝트에 접근권한이 있는 사용자

심각도와 KISA 매핑 상태로 필터링할 수 있다. 결과 심각도는 `CRITICAL`, `HIGH`, `MEDIUM`, `LOW`, `UNKNOWN` 중 하나이며, 신뢰도는 `HIGH`, `MEDIUM`, `LOW`, `UNKNOWN` 중 하나다. 각 결과에는 엔진 규칙 식별자(`engine_rule_id`), 진단 항목 명칭, 분석 시점 기준 식별자가 포함된다. 매핑 상태는 `kisa_code`가 있는지에 따라 `KISA_MAPPED` 또는 `UNMAPPED`로 계산하며, 권한 있는 사용자는 두 결과를 모두 조회할 수 있다. KISA 카탈로그 API는 49개 기준 항목만 반환한다.

### `GET /api/findings/{finding_id}`

권한: 진단 결과가 속한 프로젝트에 접근권한이 있는 사용자

엔진 규칙 식별자(`engine_rule_id`), 진단 항목 명칭, KISA 매핑 항목 식별자(`kisa_code`), 분석 시점 기준 식별자, 탐지 근거, 상대 파일 경로와 시작·끝 줄, 제한된 코드 조각, 조치 권고와 결과 상세를 조회한다. 코드 조각은 분석 시점 스냅샷의 취약 범위 주변 문맥이며 전체 소스 조회 기능이 아니다. 원본 분석 결과는 관리자 전용 필드로 분류한다.

## KISA 카탈로그

### `GET /api/catalog`

권한: 로그인 사용자

49개 항목의 식별자, 분류, 항목 번호, 명칭, 설명과 구현 상태를 조회한다.

### `GET /api/catalog/{kisa_code}`

권한: 로그인 사용자

특정 진단 기준을 조회한다.

### `POST /api/catalog`

권한: 관리자

신규 진단 항목을 등록한다. 카탈로그 항목에는 식별자, 명칭, 설명, 기준 식별자, 분류, 항목 번호, 참조 정보, 활성 여부, 기본 심각도, 구현 상태를 입력한다. `kisa_code`가 기존 항목과 중복되면 등록을 거부한다. 중복 등록 거부는 분석 중복 실행(`POST /api/analyses`)과 동일하게 `409 Conflict`로 응답한다.

### `PATCH /api/catalog/{kisa_code}`

권한: 관리자

카탈로그 항목의 설명, 참조 정보, 활성 여부, 기본 심각도, 구현 상태와 조치 권고를 수정한다.

MVP에서는 카탈로그 항목 삭제 API를 제공하지 않는다. 더 이상 사용하지 않는 항목은 `active` 값을 `false`로 변경한다.

## 역할별 권한 요약

| 기능 | 관리자 | 일반 사용자 |
|---|---|---|
| 로그인 | 가능 | 가능 |
| 프로젝트 조회 | 전체 | 권한 있는 프로젝트 |
| 프로젝트 생성·수정 | 가능 | 불가 |
| 접근권한 관리 | 가능 | 불가 |
| 소스 등록 | 가능 | 불가 |
| 분석 실행 | 가능 | 불가 |
| 분석 결과 조회 | 전체 | 권한 있는 프로젝트 |
| 오류 상세와 실행 로그 | 가능 | 불가 |
| 카탈로그 조회 | 가능 | 가능 |
