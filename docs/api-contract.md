# API 계약 초안

이 문서는 MVP 구현 전에 프론트와 백엔드가 공유하는 API 방향을 정리한다. 실제 경로와 필드가 변경되면 관련 ADR과 요구사항 검증표를 함께 갱신한다.

## 공통 규칙

- 프론트엔드가 사용하는 공개 경로는 `/api`다. 개발 프록시가 `/api`를 제거해 백엔드의 실제 경로로 전달한다.
- 백엔드에 직접 요청할 때는 `/auth`, `/projects`처럼 `/api`가 없는 경로를 사용한다.
- 보호된 API는 Bearer 토큰을 요구한다.
- 관리자 전용 API는 일반 사용자 요청을 거부한다.
- 프로젝트, 분석, 진단 결과는 저장된 관계와 사용자 권한을 함께 검증한다.
- 권한이 없는 프로젝트 자원은 404로 응답한다.
- 관리자 전용 오류와 실행 로그는 일반 사용자 응답에 포함하지 않는다.
- `source_snapshot_location` 같은 서버 내부 저장 위치는 어떤 API 응답에도 포함하지 않는다.

## 인증

### `POST /api/auth/login`

권한: 공개

요청:

```json
{
  "email": "admin@secscan.local",
  "password": "비밀번호"
}
```

`email`은 MVP의 계정 식별자이며 유효한 이메일 형식이어야 한다.

응답:

```json
{
  "access_token": "jwt-token",
  "token_type": "bearer",
  "role": "ADMIN"
}
```

MVP에서는 회원가입과 비밀번호 재설정을 제공하지 않는다.

## 프로젝트

### `GET /api/projects`

권한: 로그인 사용자

관리자는 전체 프로젝트를, 일반 사용자는 접근권한이 있는 프로젝트만 조회한다.

관리자는 `PROJECT_ACCESS` 행이 없어도 모든 프로젝트를 조회하고 관리한다. 일반 사용자만 프로젝트별 접근권한 행이 필요하다.

일반 사용자는 권한이 부여된 프로젝트를 분석 이력이 없어도 조회할 수 있다. 이 경우 화면은 분석 이력이 없다는 빈 상태를 표시한다.

접근권한 해제는 프로젝트와 분석 데이터를 삭제하지 않는다. 권한이 해제된 일반 사용자의 목록에서는 해당 프로젝트를 숨기고, 직접 주소 접근은 404로 응답한다.

### `POST /api/projects`

권한: 관리자

프로젝트명과 선택 입력인 설명을 입력받는다. `target_languages`는 프로젝트 생성 API에서 받지 않는다. MVP의 소스 유형은 파일 업로드이며, 소스 등록이 성공하면 시스템이 업로드 파일에서 `JAVA`, `JAVASCRIPT`, `PYTHON` 언어를 자동 식별해 `target_languages`, `source_type`, `source_location`을 기록한다.

같은 프로젝트명을 등록하면 시스템이 뒤 번호를 붙여 고유한 표시명을 저장한다. 예를 들어 `보안 교육 샘플`이 이미 있으면 다음 등록명은 `보안 교육 샘플 (1)`이 된다.

### `PATCH /api/projects/{project_id}`

권한: 관리자

프로젝트명과 설명을 수정한다. `target_languages`는 소스 등록 과정에서 시스템이 갱신하므로 요청으로 수정할 수 없다.

MVP에서는 `DELETE /api/projects/{project_id}`를 제공하지 않는다. 프로젝트 삭제에 따른 분석 이력과 진단 결과 처리 정책은 후속 범위에서 결정한다.

### `POST /api/projects/{project_id}/access`

권한: 관리자

프로젝트에 일반 사용자의 접근권한을 부여한다.

### `DELETE /api/projects/{project_id}/access/{user_id}`

권한: 관리자

프로젝트 접근권한을 해제한다.

## 분석

### `POST /api/analyses`

권한: 관리자

프로젝트와 소스 파일을 받아 분석 작업을 생성한다. 분석은 `PENDING`, `RUNNING`, `COMPLETED`, `FAILED` 상태를 사용한다.

분석 행은 생성 시점의 분석 엔진 또는 방식과 실제 적용할 언어 목록을 함께 저장한다. 이 값은 이후 프로젝트의 분석 언어 설정이 바뀌어도 변경하지 않는다.

`FAILED`의 세부 원인은 관리자 응답의 오류 코드와 상세 메시지로 제공한다. 일반 사용자 응답에는 일반적인 실패 안내만 제공한다.

같은 프로젝트에 `PENDING` 또는 `RUNNING` 분석이 있으면 새 분석을 생성하지 않고 409 응답과 현재 분석 정보를 제공한다.

### `GET /api/analyses?project_id={project_id}`

권한: 해당 프로젝트 접근권한이 있는 사용자

프로젝트의 분석 이력을 조회한다. 일반 사용자 응답은 상태, 시각, 실행 요약, 일반적인 실패 안내만 포함한다. 관리자 응답은 여기에 분석 엔진 또는 방식, 분석 시점 언어 목록, 상세 오류와 실행 로그를 추가한다. 서버 내부 스냅샷 위치와 원본 결과 경로는 두 응답 모두에 포함하지 않는다.

일반 사용자는 상태와 결과 요약을 조회할 수 있다. `FAILED` 상태의 상세 오류와 실행 로그는 일반 사용자 응답에 포함하지 않고, 일반적인 실패 안내만 제공한다.

### `GET /api/analyses/{analysis_id}`

권한: 분석이 속한 프로젝트에 접근권한이 있는 사용자

분석 상태와 결과 요약을 조회한다.

## 진단 결과

### `GET /api/findings?analysis_id={analysis_id}`

권한: 분석이 속한 프로젝트에 접근권한이 있는 사용자

심각도와 KISA 매핑 상태로 필터링할 수 있다. 각 결과에는 진단 항목 식별자, 명칭, 분석 시점 기준 식별자가 포함된다. 매핑 상태는 `kisa_code`가 있는지에 따라 `KISA_MAPPED` 또는 `UNMAPPED`로 계산하며, 권한 있는 사용자는 두 결과를 모두 조회할 수 있다. KISA 카탈로그 API는 49개 기준 항목만 반환한다.

### `GET /api/findings/{finding_id}`

권한: 진단 결과가 속한 프로젝트에 접근권한이 있는 사용자

진단 항목 식별자, 명칭, 분석 시점 기준 식별자, 탐지 근거, 파일 위치, 조치 권고와 결과 상세를 조회한다. 원본 분석 결과는 관리자 전용 필드로 분류한다.

## KISA 카탈로그

### `GET /api/catalog`

권한: 로그인 사용자

49개 항목의 식별자, 분류, 항목 번호, 명칭, 설명과 구현 상태를 조회한다.

### `GET /api/catalog/{kisa_code}`

권한: 로그인 사용자

특정 진단 기준을 조회한다.

### `POST /api/catalog`

권한: 관리자

신규 진단 항목을 등록한다. 카탈로그 항목에는 식별자, 명칭, 설명, 기준 식별자, 분류, 항목 번호, 참조 정보, 활성 여부, 기본 심각도, 구현 상태를 입력한다. `kisa_code`가 기존 항목과 중복되면 등록을 거부한다.

### `PATCH /api/catalog/{kisa_code}`

권한: 관리자

카탈로그 항목의 설명, 참조 정보, 활성 여부, 기본 심각도, 구현 상태와 조치 권고를 수정한다.

MVP에서는 카탈로그 항목 삭제 API를 제공하지 않는다. 더 이상 사용하지 않는 항목은 `active` 값을 `false`로 변경한다.

## 역할별 권한 요약

| 기능 | 관리자 | 일반 사용자 |
|---|---|---|
| 로그인 | 가능 | 가능 |
| 프로젝트 조회 | 전체 | 권한 있는 프로젝트 |
| 프로젝트 생성·수정 | 가능 | 불가 |
| 접근권한 관리 | 가능 | 불가 |
| 소스 등록 | 가능 | 불가 |
| 분석 실행 | 가능 | 불가 |
| 분석 결과 조회 | 전체 | 권한 있는 프로젝트 |
| 오류 상세와 실행 로그 | 가능 | 불가 |
| 카탈로그 조회 | 가능 | 가능 |
