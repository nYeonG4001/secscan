# 요구사항 검증표

원본 요구사항 50개를 에픽, 세부 작업, 구현 대상, 테스트와 실행 증거에 연결하는 문서다.

원본 파일은 저장소에 커밋하지 않고 별도 보관한다. 이 표의 요구사항 이름과 검증 목표는 원본 문구를 기준으로 작성한다.

## 사용 상태

- `미착수`: 구현과 테스트가 없음
- `설계 완료`: 설계 문서와 작업 번호는 있으나 구현과 테스트가 없음
- `진행`: 일부 구현 또는 테스트가 있음
- `검증 대기`: 구현은 있으나 실행 증거 확인이 필요함
- `완료`: 구현, 테스트, 실행 증거가 모두 확인됨
- `해석 대기`: 원본만으로 범위를 확정하기 어려움

## 등록 규칙

- 새 구현을 시작할 때 관련 요구사항 행과 세부 작업의 상태를 함께 갱신한다.
- 테스트를 추가하면 테스트 파일 경로를 기록한다.
- 화면, API 응답, 로그, 캡처는 증거 열에 기록한다.
- 요구사항 해석이 바뀌면 `docs/requirements-interpretation.md`와 관련 ADR을 함께 갱신한다.
- 요구사항을 MVP에서 후순위로 미루더라도 원본 행을 삭제하거나 내용을 축소하지 않는다.
