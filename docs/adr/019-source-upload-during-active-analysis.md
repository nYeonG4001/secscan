# ADR-019: 진행 중 분석이 있는 프로젝트의 소스 업로드 제한

## Context

E1은 프로젝트마다 `PENDING` 또는 `RUNNING` 분석을 하나만 허용한다. 분석별 스냅샷을 사용하면 진행 중 분석은 기존 소스를 계속 사용하고 프로젝트 현재 소스만 새 ZIP으로 교체하는 구현도 가능하다. 그러나 이 경우 화면에서 현재 소스와 진행 중 분석의 대상 소스가 달라져 사용자가 상태를 해석하기 어려워진다.

## Decision

- 프로젝트에 `PENDING` 또는 `RUNNING` 분석이 있으면 새 소스 업로드를 허용하지 않는다.
- 서버는 `409 Conflict`로 거부하고, 프론트는 `분석이 끝난 뒤 업로드할 수 있습니다.`라고 안내한다.
- 해당 분석이 `COMPLETED` 또는 `FAILED`가 되면 ADMIN은 새 ZIP을 등록할 수 있다.
- 업로드 예약 대기열은 MVP에서 제공하지 않는다.
- 소스 업로드와 분석 실행은 ADR-006에 따라 별도 행동으로 유지한다. 새 ZIP 업로드는 분석을 자동 실행하지 않는다.

## Considered alternatives

- 진행 중에도 업로드를 허용한다. 분석 스냅샷 덕분에 기술적으로 가능하지만 현재 소스와 분석 대상이 달라져 사용자 흐름과 상태 표시가 복잡해져 선택하지 않는다.
- 분석 완료 뒤 업로드 요청을 자동 실행하는 대기열을 만든다. 관리자는 편리하지만 예약 상태, 취소, 순서, 실패 재시도 기능이 추가돼 선택하지 않는다.
- 진행 중 분석이 있으면 업로드를 거부한다. 프로젝트 상태를 단순하게 유지하고 기존 화면 설계의 비활성화 규칙과 일치해 선택한다.

## Consequences

- 관리자는 진행 중 분석이 끝날 때까지 새 소스를 올릴 수 없다.
- E3 업로드 API는 활성 분석 상태를 조회하고 409을 반환해야 한다.
- E3-07은 비활성 버튼과 409 안내를 제공하고, E3-08은 `PENDING`, `RUNNING`, `COMPLETED`, `FAILED` 상태별 업로드 가능 여부를 검증한다.
