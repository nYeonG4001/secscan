# ADR-018: 지원 소스 파일과 자동 언어 감지

## Context

ZIP 소스 프로젝트에는 Java, JavaScript, Python 소스 외에도 설정 파일, 문서, 이미지, 바이너리, 의존성, 생성 결과물이 함께 들어갈 수 있다. 소스 확장자만 포함한 ZIP을 강제하면 정상 프로젝트 구조를 거부하게 된다. 반대로 모든 일반 파일을 분석 후보로 넘기면 분석 시간과 결과 품질이 나빠진다.

SFR-004와 DAR-003은 프로젝트의 분석 대상 언어를 저장하도록 요구하고, TST-004는 업로드 소스에서 분석 대상 언어를 식별하도록 요구한다. MVP는 Java, JavaScript, Python을 우선 지원한다.

## Decision

- ADR-016에서 허용한 일반 파일과 디렉터리는 ZIP에 보존한다. 설정 파일, 문서, 이미지, 바이너리가 있다는 이유만으로 ZIP 전체를 거부하지 않는다.
- 언어 감지와 이후 분석 후보는 아래 정규 파일 확장자만 사용한다.

| 언어 | 확장자 |
|---|---|
| Java | `.java` |
| JavaScript | `.js`, `.jsx`, `.mjs`, `.cjs` |
| Python | `.py` |

- 관리자는 프로젝트 생성이나 업로드 화면에서 분석 언어를 선택하지 않는다. 시스템이 검증을 통과한 ZIP의 실제 지원 소스 파일을 검사해 `target_languages`를 기록한다.
- 지원 소스 파일이 하나도 없으면 업로드를 거부한다.
- `.ts`, `.tsx`는 JavaScript와 유사하지만 MVP의 지원 언어에 포함하지 않는다. 추가 언어 수집, 파싱, 진단 구조를 확장해야 한다는 요구사항에 따라 TypeScript는 핵심 E3부터 E7 작업과 검증이 끝난 뒤 시간이 남을 때만 추가하는 선택 작업으로 둔다.
- ZIP 안의 다른 압축 파일은 일반 파일로만 취급하고 자동으로 다시 압축 해제하지 않는다.
- `node_modules`, `venv`, `.venv`, `__pycache__`, `dist`, `build`, `target` 같은 의존성 또는 생성 결과물 디렉터리는 E4 분석 입력을 만들 때 제외한다. E3는 원본 소스 구조를 임의로 삭제하지 않는다.

## Considered alternatives

- 지원 소스 확장자 외 파일이 하나라도 있으면 ZIP을 거부한다. 설정 파일과 문서를 포함한 정상 프로젝트를 막으므로 선택하지 않는다.
- 모든 일반 파일을 언어 감지와 분석 후보로 사용한다. 바이너리와 생성 결과물까지 처리하게 되어 선택하지 않는다.
- 일반 파일은 보존하고, 명시한 지원 소스 확장자만 감지와 분석 후보로 사용한다. 정상 프로젝트 구조와 제한된 MVP 분석 범위를 함께 유지할 수 있어 선택한다.

## Consequences

- 지원하지 않는 언어만 포함된 ZIP은 업로드할 수 없다.
- TypeScript 확장자는 MVP에서 지원 소스로 감지하지 않는다. 핵심 MVP가 완료된 뒤 시간이 남을 때 TypeScript 감지, Semgrep 설정, KISA 매핑, 취약·정상 샘플 테스트를 함께 추가한다.
- E3-07은 지원 언어 소스가 없을 때 사용자가 이해할 수 있는 안내와 재시도 방법을 제공해야 한다.
- E3-08은 Java, JavaScript, Python의 복수 감지와 지원 소스 부재 거부를 검증한다.
- E4는 분석 실행 전에 생성 결과물과 의존성 디렉터리를 제외한 지원 소스 파일만 엔진에 전달한다.
