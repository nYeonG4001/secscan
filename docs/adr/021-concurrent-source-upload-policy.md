# ADR-021: 프로젝트별 동시 소스 업로드 제한

## Context

같은 관리자가 업로드 버튼을 두 번 누르거나 여러 관리자가 같은 프로젝트에 거의 동시에 ZIP을 올릴 수 있다. ADR-017의 원자적 교체는 파일 손상을 막지만, 두 요청을 모두 성공시키면 마지막 요청이 다른 요청의 현재 소스를 조용히 덮어쓸 수 있다.

## Decision

- 프로젝트마다 진행 중인 소스 업로드는 한 건만 허용한다.
- 첫 업로드가 검증과 현재 소스 교체를 마칠 때까지 같은 프로젝트의 새 업로드 요청은 `409 Conflict`와 `UPLOAD_IN_PROGRESS` 코드로 거부한다.
- 업로드 잠금은 임시 처리 상태이며 `PROJECT`에 저장하는 필드나 사용자에게 보이는 이력이 아니다.
- 업로드 처리의 성공, 실패, 예외, 취소 경로 모두에서 잠금을 해제한다. 두 번째 요청은 임시 작업영역을 만들기 전에 거부한다.
- MVP의 단일 백엔드 인스턴스에서는 프로세스 안의 프로젝트별 잠금으로 구현할 수 있다. 여러 인스턴스로 확장할 때는 인스턴스 간에도 같은 프로젝트를 한 번만 처리하도록 공유 잠금 방식으로 교체한다.
- 프론트는 업로드 진행 중 같은 Drawer의 중복 제출을 막고, 서버의 `UPLOAD_IN_PROGRESS` 응답은 `다른 업로드가 진행 중입니다.`로 표시한다.

## Considered alternatives

- 마지막에 완료된 업로드를 현재 소스로 사용한다. 구현은 단순하지만 사용자가 어느 ZIP이 최종 등록됐는지 예측하기 어려워 선택하지 않는다.
- 업로드 대기열을 제공한다. 순서, 취소, 실패, 상태 표시가 추가돼 MVP 범위를 넘으므로 선택하지 않는다.
- 프로젝트별 업로드를 한 건으로 제한한다. 결과가 명확하고 분석 실행의 단일 활성 상태 정책과도 일관돼 선택한다.

## Consequences

- 관리자는 업로드가 끝날 때까지 같은 프로젝트에 다른 ZIP을 올릴 수 없다.
- E3 업로드 API는 `UPLOAD_IN_PROGRESS` 오류 코드와 409 응답을 제공해야 한다.
- E3-08은 첫 업로드가 진행 중일 때 두 번째 요청이 임시 작업영역을 만들지 않고 거부되는지 검증해야 한다.
