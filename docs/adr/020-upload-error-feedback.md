# ADR-020: 업로드 실패 안내와 재시도 정책

## Context

E3 업로드는 파일 크기 제한, 압축 해제 제한, ZIP 구조 검증, 지원 언어 감지, 진행 중 분석 상태, 네트워크 오류처럼 서로 다른 실패 원인을 가질 수 있다. 모든 오류를 하나의 문구로 표시하면 사용자가 다음 행동을 알기 어렵다. 반대로 서버 예외와 원본 경로를 그대로 표시하면 내부 경로와 보안 검증 방식을 노출할 수 있다.

## Decision

- 프론트는 내부 예외나 원본 ZIP 경로를 표시하지 않고, 사용자가 취할 행동이 다른 안전한 오류 범주만 구분한다.

| 상황 | 사용자 안내 | 다음 행동 |
|---|---|---|
| ZIP 원본 크기 초과 | `25MB 이하 ZIP만 업로드할 수 있습니다.` | 파일을 다시 선택 |
| 압축 해제 제한 초과 | `ZIP 압축 해제 제한을 초과했습니다.` | 불필요한 파일을 제거한 뒤 다시 선택 |
| 위험한 ZIP 구조 | `안전하지 않은 ZIP입니다.` | 경로와 링크를 확인한 뒤 다시 선택 |
| 지원 소스 부재 | `지원하는 소스 파일이 없습니다.` | 지원 소스가 포함된 ZIP을 선택 |
| 진행 중 분석 | `분석이 끝난 뒤 업로드할 수 있습니다.` | 분석 종료 뒤 다시 시도 |
| 다른 업로드 진행 중 | `다른 업로드가 진행 중입니다.` | 업로드 종료 뒤 다시 시도 |
| 네트워크 또는 서버 오류 | `업로드에 실패했습니다. 다시 시도해 주세요.` | 명시적으로 다시 시도 |

- 자동 재시도는 하지 않는다. 파일 검증 실패와 서버 상태 변경 가능성이 있으므로 사용자가 명시적으로 다시 시도해야 한다.
- 업로드 중 진행률과 취소 행동을 제공한다. 취소는 브라우저 요청을 중단하고 서버는 임시 작업영역을 정리한다.
- 취소 요청이 서버의 현재 소스 교체 완료와 경합할 수 있으므로, 프론트는 취소 뒤 프로젝트 상태를 다시 조회해 실제 결과를 확인한다.
- 실패한 ZIP과 실패한 임시 작업영역은 보관하지 않는다.

## Considered alternatives

- 모든 실패에 같은 일반 오류를 사용한다. 다음 행동을 알 수 없어 선택하지 않는다.
- 서버 오류 전문과 거부된 원본 경로를 그대로 표시한다. 내부 정보 노출 위험이 있어 선택하지 않는다.
- 오류 범주별로 짧은 안내와 명시적 재시도를 제공한다. 사용자 행동을 안내하면서 내부 정보를 숨길 수 있어 선택한다.

## Consequences

- 백엔드는 프론트가 구분할 수 있는 안정적인 오류 코드 또는 상태를 제공해야 한다. 상세 원인과 경로는 서버 로그에만 남긴다.
- E3-07은 Drawer의 선택, 업로드 중, 취소, 실패, 성공 상태를 구현한다.
- E3-08은 오류 범주별 응답과 취소 뒤 임시 작업영역 정리를 검증한다.
