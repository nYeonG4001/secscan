# ADR-006: MVP 소스 등록 범위

## Context

SFR-007은 업로드, 저장소 연계, 내부 경로 등 제안 방식으로 소스코드를 등록하고 관리할 수 있어야 한다고 요구한다. 원본 요구사항은 MVP에서 한 가지 방식을 선택하는 것을 막지 않는다.

## Decision

전체 제품은 파일 업로드, Git 저장소, 기관 내부 경로를 지원할 수 있도록 확장성을 고려한다. 다만 MVP에서는 파일 업로드만 구현한다. `source_type`과 `source_location`은 이후 등록 방식을 추가할 수 있도록 유지한다.

Git 저장소와 기관 내부 경로는 후속 에픽으로 미룬다. 기관 내부 경로를 추가할 때도 허용된 루트와 접근 권한을 검증하며, 사용자가 입력한 임의의 서버 경로를 그대로 열지 않는다.

프로젝트 생성, 소스 업로드, 분석 실행은 별도 흐름으로 둔다. 프로젝트 생성 시 관리자는 소스 위치를 직접 입력하지 않고, 업로드가 성공한 뒤 시스템이 관리하는 위치값을 `source_location`에 기록한다.

분석을 생성할 때는 업로드한 소스를 별도 스냅샷으로 복사한다. MVP 기간에는 분석 스냅샷을 자동 삭제하지 않고 보관한다. 보존 기간, 용량 한도, 자동 정리 작업은 실제 운영 환경과 저장공간 기준이 정해진 후 후속 범위에서 결정한다.

## Consequences

- MVP의 구현과 보안 검증 범위를 파일 업로드에 집중할 수 있다.
- 이후 저장소 또는 내부 경로를 추가할 때 Project 모델을 다시 바꾸지 않아도 된다.
- 임의 파일 경로를 받아 분석하는 기능은 제공하지 않는다.
- MVP에서는 분석 이력과 연결된 소스 스냅샷을 안정적으로 조회할 수 있다.
- 스냅샷 자동 삭제 기능과 저장공간 정리 정책은 MVP 완료 조건에 포함하지 않는다.
