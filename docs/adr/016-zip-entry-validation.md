# ADR-016: ZIP 항목 경로와 링크 검증

## Context

ZIP은 파일명에 상대 경로 이동, 절대 경로, 운영체제별 경로 표현을 넣을 수 있다. 이를 검증하지 않고 압축을 풀면 작업영역 밖 파일을 덮어쓰는 ZIP Slip이 발생할 수 있다. ZIP은 심볼릭 링크처럼 보이는 항목도 담을 수 있으며, 링크가 작업영역 밖 경로를 가리키면 이후 분석 과정에서 의도하지 않은 파일을 읽을 수 있다.

## Decision

- ZIP 항목을 압축 해제하기 전에 전체 목록을 검사한다. 위험한 항목이 하나라도 있으면 ZIP 전체를 거부하고 어떤 항목도 작업영역에 생성하지 않는다.
- 경로를 자동 수정하거나 위험한 항목만 건너뛰지 않는다. 원본 소스의 디렉터리 구조를 바꾸거나 파일 충돌을 만드는 동작을 피하기 위해서다.
- 다음 항목을 거부한다.
  - 절대 경로
  - `..`를 이용한 상위 경로 이동
  - Windows 드라이브 경로와 UNC 경로
  - NUL 문자가 포함된 경로
  - 정규화 뒤 문자 단위로 같은 대상 경로가 되는 중복 항목
  - 대소문자만 다른 대상 경로가 되는 항목
  - 심볼릭 링크, 하드 링크, 그 밖의 링크성 항목
- 허용된 각 항목도 대상 경로를 작업영역 기준으로 해석한 뒤, 해석된 경로가 작업영역 내부인지 다시 확인한다.
- 사용자 화면에는 `안전하지 않은 ZIP입니다.`라는 일반 안내만 표시한다. 거부된 원본 경로는 화면에 그대로 노출하지 않는다.
- 문자 단위가 완전히 같은 중복 경로는 어떤 파일시스템에서도 항상 거부한다. 대소문자만 다른 경로도 같은 대상 경로로 간주해 거부한다. 현재 `docker-compose.yml`의 `./backend:/app` bind mount와 미확정 배포 환경 때문에 실제 저장 경로의 대소문자 구분 여부를 보장할 수 없기 때문이다.
- 저장 경로가 host bind mount와 분리된 대소문자 구분 전용 저장소로 확정되고, 모든 배포 환경에서 그 특성이 보장되면 대소문자 경로 정책을 다시 검토한다.

## Considered alternatives

- 위험한 경로를 안전한 이름으로 자동 수정한다. 업로드 성공률은 높지만 원본 구조를 바꾸고 서로 다른 파일을 충돌시킬 수 있어 선택하지 않는다.
- 압축 해제 후 검사한다. 검사 전에 작업영역 밖 쓰기가 일어날 수 있어 선택하지 않는다.
- 심볼릭 링크를 작업영역 내부 경로일 때만 허용한다. 링크의 재해석과 이후 분석 도구의 동작까지 검증해야 하므로 교육용 MVP 범위를 넘는다.
- 모든 링크를 거부하고 항목을 사전 검증한다. 정상 소스 ZIP에는 영향이 작고 ZIP Slip과 링크 우회를 함께 막을 수 있어 선택한다.

## Consequences

- 링크를 포함한 일부 정상 프로젝트 ZIP도 업로드할 수 없다.
- E3-04, E3-05는 실제 파일 생성 전 검증과 작업영역 내부 재확인을 구현한다.
- E3-08은 경로 조작, 절대 경로, 링크, 문자 단위 중복 경로, 대소문자만 다른 경로 ZIP이 전체 거부되는지 검증한다.
