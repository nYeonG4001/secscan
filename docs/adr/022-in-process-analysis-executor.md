# ADR-022: 단일 인스턴스 분석 실행기

**Context**: 분석 요청은 응답을 기다리지 않고 상태 화면에서 진행 상황을 확인할 수 있어야 한다. 현재 MVP는 단일 Docker 인스턴스로 운영하며, 별도 메시지 큐나 워커 인프라는 아직 없다. 같은 프로젝트는 E1의 제약으로 활성 분석을 하나만 가질 수 있지만, 서로 다른 프로젝트의 분석이 동시에 시작되면 Semgrep 프로세스가 제한 없이 생성될 수 있다.

**Decision**: 앱이 관리하는 `ThreadPoolExecutor(max_workers=1)`를 분석 실행기로 사용한다. 관리자 요청은 분석 행을 `PENDING`으로 저장한 뒤 즉시 응답하고, 실행기는 별도 DB 세션으로 작업을 수행한다. 실행기는 `PENDING → RUNNING → COMPLETED` 또는 `FAILED`만 허용하며, 재실행은 기존 행을 변경하지 않고 새 분석 행을 만든다.

서버 시작 시 남아 있는 `PENDING` 또는 `RUNNING` 분석은 자동 재개하지 않고 `FAILED`로 전환한다. 관리자에게는 분석 중단 안내를 제공하고 새 분석 실행을 허용한다. 실행 시간과 자원 제한, Semgrep subprocess 종료는 ADR-025와 E4-05에서 구현한다.

**Alternatives**: 요청 안에서 동기 실행, FastAPI `BackgroundTasks`만 사용, Celery 또는 Redis 기반 별도 작업 큐, 단일 인스턴스 내부 제한 실행기

**Consequences**: 단일 실행기는 한 분석이 실행 중일 때 다른 프로젝트의 분석을 `PENDING`으로 대기시켜 컨테이너 자원 고갈을 줄인다. 별도 큐 없이도 상태 폴링 화면을 제공할 수 있지만, 서버 재시작 뒤 진행 중이던 분석은 복구하지 않는다. 다중 인스턴스나 더 높은 처리량이 필요해지면 공유 작업 큐와 분산 잠금으로 교체한다.
