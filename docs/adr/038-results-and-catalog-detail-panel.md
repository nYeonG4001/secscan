# ADR-038: 결과·카탈로그 조회 상세 패널

**Context**: 완료 분석의 Finding과 KISA 카탈로그는 목록에서 여러 항목을 빠르게 대조하면서 한 항목의 근거를 확인해야 한다. 입력 작업용 `ActionDrawer`는 오버레이와 메인 스크롤 잠금을 사용하므로, 결과를 비교하는 조회 화면에 그대로 적용하면 목록 문맥을 잃는다. 분석 실행 로그는 Finding 하나가 아니라 분석 실행 전체에 연결된 정보다.

**Decision**: 진단 결과와 카탈로그는 왼쪽 목록과 오른쪽 조회 상세 패널을 함께 표시한다. 두 영역은 독립적으로 스크롤하며, 상세 패널을 닫아도 목록의 필터·페이지·스크롤 위치를 유지한다. 결과 상세는 심각도와 진단 항목명, 위치, 메시지, 탐지 근거, 코드 조각, 조치 권고 순으로 표시한다. `Finding.raw_result`는 ADMIN에게만 표시한다. 분석 실패의 오류 코드·상세 메시지·실행 로그와 재실행 행동은 개별 Finding 패널이 아니라 분석 상태 화면에서 ADMIN에게만 표시한다. 카탈로그의 USER는 읽기 전용이고, ADMIN만 같은 패널을 수정 상태로 전환한다.

**Alternatives**: Finding·카탈로그별 별도 상세 페이지, 모든 상세를 400px `ActionDrawer`로 통일, 실행 로그를 각 Finding 상세에 반복 표시

**Consequences**: 화면은 넓은 데스크톱 작업 영역을 전제로 하며 작은 화면에서는 상세 패널을 우선 표시하도록 조정해야 한다. 프론트 테스트는 역할별 원본 결과·실행 로그 노출, 목록 상태 유지와 독립 스크롤을 검증한다. 입력 ActionDrawer의 접근성·스크롤 잠금 규칙은 결과와 카탈로그의 조회 패널에 적용하지 않는다.
