# ADR-034: 원본 분석 결과의 분리 보존과 정규화 원자성

**Context**: Semgrep 실행 결과 전체와 각 Finding 원본 결과를 모두 저장하면 같은 `results[]` 항목이 분석과 Finding에 중복된다. 반대로 결과 항목을 일부만 건너뛰고 분석을 완료하면 사용자는 분석이 성공했다고 보지만 일부 경고가 조용히 사라질 수 있다. DAR-006, DAR-008, DAR-009는 결과 원본 정보와 분석 시점 정보를 보존하도록 요구하며, ADR-009는 원본 결과를 관리자 전용으로 제한한다.

**Decision**: 완료 분석의 `ANALYSIS.raw_result`에는 엔진 이름과 버전, 규칙 고정본 식별자, 출력 형식 버전, 종료 상태, 결과 수 등 안전한 실행 메타데이터만 저장한다. 전체 Semgrep `results[]` 배열은 저장하지 않는다. 저장된 각 `FINDING.raw_result`에는 그 Finding을 만든 원본 Semgrep 결과 객체를 보존하고, 이 필드는 ADMIN에게만 제공한다. `ANALYSIS.summary`는 일반 사용자도 볼 수 있는 결과 집계로 유지한다.

파싱 또는 정규화할 수 없는 Semgrep 결과 항목이 하나라도 있으면 해당 분석은 `ENGINE_OUTPUT_INVALID`로 실패한다. Finding 저장은 하나의 DB 트랜잭션으로 처리하고 모두 롤백해, 일부 결과만 성공으로 남기지 않는다. ADR-033이 정한 코드 조각 추출 실패는 보조 정보 실패이므로 이 규칙의 대상이 아니다.

**Alternatives**: 분석 전체 원본과 Finding 원본을 모두 저장, 분석 전체 원본만 저장, 일부 정규화 실패 항목을 건너뛰고 완료 처리, 원본 결과를 저장하지 않음

**Consequences**: 완료 분석에서 원본 Finding 결과는 한 번만 저장되고, 실행 메타데이터와 사용자용 집계를 분리할 수 있다. 예상하지 못한 엔진 출력은 조용히 누락되지 않고 실패 상태로 드러난다. E5 정규화 서비스는 트랜잭션 경계와 전체 롤백 테스트를 구현해야 한다.

**References**: ADR-007, ADR-009, ADR-023, ADR-026, ADR-033, SFR-014, DAR-006, DAR-008, DAR-009, SEC-003, SEC-009, QLT-004
