# ADR-015: ZIP 업로드 자원 제한

## Context

E3에서 받는 ZIP 파일은 신뢰할 수 없는 입력이다. ZIP 원본 크기만 제한하면 작은 압축 파일이 압축 해제 과정에서 디스크와 메모리를 과도하게 사용하는 압축 폭탄을 막을 수 없다. 파일 수가 매우 많거나 개별 파일이 지나치게 큰 경우에도 압축 해제와 이후 분석 작업이 서버 자원을 점유할 수 있다.

## Decision

- MVP는 ZIP 원본 크기, 실제 압축 해제 누적 크기, 파일 수, 개별 파일 크기, 압축 비율을 함께 제한한다. 압축 비율 20:1은 ZIP 항목별로 판단한다.
- 기본 제한값은 다음과 같다.

| 대상 | 기본 제한 |
|---|---:|
| ZIP 원본 파일 | 25 MB |
| 실제 압축 해제 누적 크기 | 100 MB |
| 파일 수 | 5,000개 |
| 개별 파일 크기 | 10 MB |
| 압축 비율 | 20:1 |
| 비율 검사 시작 출력 크기 | 1 MB |

- 압축 해제 전 ZIP 메타데이터만으로 허용 여부를 판단하지 않는다. 파일을 스트리밍으로 읽는 동안 실제 누적 바이트와 파일 수를 측정하고, 어느 하나라도 제한을 넘으면 즉시 중단하고 작업영역을 정리한다. 항목별 압축 비율은 스트리밍 중 실제로 소비한 압축 입력 바이트와 실제로 생성한 압축 해제 출력 바이트로 계산한다.
- 항목의 실제 압축 해제 출력이 1 MB 미만이면 압축 비율만으로 거부하지 않는다. 1 MB에 도달한 뒤 실제 출력과 실제 압축 입력의 비율이 20:1을 넘으면 즉시 중단하고 거부한다. 압축 비율은 조기 거부를 위한 보조 제한이며, 실제 압축 해제 크기 제한을 대체하지 않는다.
- 비율 검사 시작 출력 크기와 비율 제한은 다른 업로드 제한과 같이 환경 설정으로 조정할 수 있다.
- 기본 제한값은 환경 설정으로 조정할 수 있게 구현한다. 단, 기본값을 완화하거나 변경할 때는 운영 환경의 디스크와 분석 자원 영향을 함께 검토한다.
- 허용 파일 형식, ZIP 경로 검증, 심볼릭 링크, 오류 응답 문구는 E3의 별도 결정에서 정한다.

## Considered alternatives

- 제한 없이 모든 ZIP을 허용한다. 큰 교육용 프로젝트를 받을 수 있지만 압축 폭탄과 자원 고갈을 허용하게 되므로 선택하지 않는다.
- ZIP 원본 크기만 제한한다. 구현은 단순하지만 압축 해제 뒤의 실제 크기와 파일 수를 통제할 수 없으므로 선택하지 않는다.
- 원본 크기, 압축 해제 크기, 파일 수만 제한한다. 상당수 위험을 줄일 수 있지만 압축 비율이 비정상적으로 큰 입력을 일찍 차단하지 못하므로 선택하지 않는다.
- 다층 제한을 적용한다. 교육용 Java, JavaScript, Python 소스 프로젝트를 수용하면서 압축 폭탄과 과도한 분석 입력을 함께 제한할 수 있어 선택한다.

## Consequences

- 정상 입력도 제한을 초과하면 업로드가 거부될 수 있다.
- E3-07 화면은 제한을 초과한 경우 사용자가 다음에 할 수 있는 행동을 안내해야 한다.
- E3-08은 각 제한 초과와 압축 해제 중단 뒤 작업영역 정리를 검증해야 한다.
