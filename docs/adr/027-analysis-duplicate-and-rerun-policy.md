# ADR-027: 분석 중복 실행과 재실행 정책

**Context**: 같은 프로젝트에 분석 요청이 두 번 들어오면 같은 현재 소스를 중복 분석해 단일 실행기 대기열과 자원을 낭비한다. 반면 완료 또는 실패한 분석은 새 소스 등록 뒤에도 이력으로 보존해야 하며, 사용자가 같은 프로젝트를 다시 분석할 수 있어야 한다.

**Decision**: 같은 프로젝트에 `PENDING` 또는 `RUNNING` 분석이 있으면 새 `POST /api/analyses` 요청을 `409 ANALYSIS_ACTIVE`로 거부한다. 응답에는 관리자에게만 진행 중인 `analysis_id`와 `status`를 제공하고, 화면은 해당 분석 상태로 이동한다. 앱 수준 사전 확인 뒤에도 동시 요청 경합은 `uq_analyses_project_active` DB 제약 위반을 같은 409 응답으로 변환해 최종 차단한다.

완료 또는 실패한 분석의 “다시 분석”은 별도 재실행 API 없이 기존 `POST /api/analyses`를 다시 호출한다. 항상 새 `ANALYSIS` 행을 만들고, **요청 시점의 프로젝트 현재 소스**를 대상으로 한다. 과거 분석의 스냅샷을 선택해 재실행하거나 사용자에게 소스 버전을 선택하게 하는 기능은 MVP 범위에서 제외한다.

**Alternatives**: 활성 분석도 대기열에 추가, `POST /analyses/{analysis_id}/rerun` 별도 API, 과거 스냅샷으로 재실행, 기존 `POST /api/analyses` 재사용

**Consequences**: 같은 프로젝트의 중복 작업은 생성되지 않고, 다른 프로젝트의 작업만 ADR-022 실행기 대기열에서 `PENDING`으로 기다린다. 재실행의 대상이 현재 소스임을 명확히 해 분석 이력과 소스 버전 선택 기능을 혼동하지 않는다. 과거 분석 재현은 이력 조회와 저장된 스냅샷 보존으로 지원하되, 실행 기능은 후속 범위로 남는다.

**References**: ADR-022, ADR-024, SFR-008, SFR-015, DAR-005, DAR-008
