# ADR-003: KISA 카탈로그 관리와 탐지 구현 분리

**Context**: 원본 요구사항 SFR-013은 KISA 소프트웨어 개발보안 가이드 49개 보안약점 항목을 식별자, 분류, 항목 번호, 명칭, 설명 및 구현 상태와 함께 관리·조회하도록 요구한다. 원본 요구사항은 특정 분석 엔진이나 실제 탐지 항목 수를 정하지 않는다.

**Decision**: KISA 49개 항목은 모두 초기 시드 카탈로그 데이터로 관리한다. ADMIN은 공통 등록 절차로 신규 진단 항목을 추가하고, 기존 항목의 설명, 참조 정보, 활성 여부, 기본 심각도, 구현 상태와 조치 권고를 수정할 수 있다. `kisa_code`는 고유하게 검증해 중복 등록을 막는다. USER는 카탈로그를 조회만 할 수 있다. 실제 분석은 기간 안에 가능한 많은 항목을 지원하는 것을 목표로 하며, 항목별로 지원 언어, 연결된 분석 규칙, 구현 상태와 테스트 여부를 표시한다. 외부 분석 엔진을 사용할 수 있고, 필요한 매핑 또는 규칙은 별도로 추가한다.

**Alternatives**:

- KISA 49개 항목을 모두 카탈로그로 관리하고, 결정된 탐지 규칙을 항목별로 연결한다.
- 외부 분석 엔진을 연동하고 필요한 진단 규칙과 KISA 매핑을 추가한다.
- 분석 엔진과 진단 규칙을 모두 직접 구현한다.

**Consequences**: 49개 항목을 화면과 데이터에서 누락하지 않으면서 실제 지원 범위도 투명하게 표시할 수 있다. 모든 항목의 실제 탐지를 완료했다고 표시하지 않으며, 항목별 구현 상태와 테스트 범위를 계속 갱신한다. 초기 시드는 마이그레이션 또는 별도 시드 절차로 검증하고, 신규 항목 등록은 기존 분석 기능과 분리된 카탈로그 API로 처리한다.
